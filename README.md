# Управляемый автономный AI-эксперимент

Это локальный каркас для эксперимента в стиле "AI lives on computer": агент периодически просыпается, читает файловую память, делает небольшой шаг, оставляет следы для следующей сессии и засыпает.

Отличия этого варианта:

- все пользовательские артефакты должны писаться на русском языке;
- человек может направлять усилия через `GLOBAL_TARGET.md`;
- агент не должен считать `GLOBAL_TARGET.md` жёстким тикетом, но обязан сверяться с ним перед выбором действий;
- автономные сессии запускаются атомарно через временный `git worktree`;
- запуск отделён от конкретного провайдера модели: команду агента вы подключаете сами.

## Структура

```text
.
├── GLOBAL_TARGET.md              # Ваш текущий вектор: что улучшать и куда двигаться
├── SYSTEM_PROMPT.md              # Постоянные правила агента
├── AGENTS.md                     # Правила качества для агентов
├── scripts/
│   ├── run_session.py            # Сборка промпта и запуск одной сессии в текущей папке
│   └── session_transaction.py    # Атомарный запуск через временный git worktree
├── state/
│   ├── active_prompt.md          # Промпт, собранный для текущей сессии
│   ├── current_plan.md           # Рабочий план агента
│   ├── external_messages.md      # Сообщения от человека между сессиями
│   ├── questions/                # Вопросы агента и ответы создателя
│   ├── last_session.md           # Письмо следующей сессии
│   └── session_counter.txt       # Номер следующей сессии
├── logs/
│   └── history.md                # Хронология запусков и заметок
├── knowledge/                    # Устойчивые знания и наблюдения
├── projects/                     # Долгие проекты агента
├── tools/                        # Инструменты, которые агент создаёт для себя
└── tests/                        # Тесты runner'ов и транзакционной логики
```

## Быстрый старт

Проверить сборку промпта без запуска агента:

```bash
python scripts/run_session.py --dry-run
```

Для настоящего автономного режима используйте транзакционный runner:

```bash
python scripts/session_transaction.py --agent-command 'your-agent --cwd "{ROOT}" --prompt-file "{PROMPT_FILE}"'
```

Плейсхолдеры в команде агента:

- `{PROMPT_FILE}` - путь к собранному промпту;
- `{ROOT}` - корень временного worktree сессии;
- `{SESSION}` - номер сессии.

Если агент читает промпт из stdin:

```bash
python scripts/session_transaction.py --agent-command 'cat "{PROMPT_FILE}" | your-agent --cwd "{ROOT}"'
```

## Атомарность

`session_transaction.py` обеспечивает правило: успешная сессия применяется целиком, упавшая сессия не меняет основной проект.

Порядок работы:

1. Проверяет, что основной проект является Git-репозиторием.
2. Проверяет, что основной worktree чистый.
3. Берёт `.session.lock`, чтобы две сессии не шли одновременно.
4. Создаёт временный `git worktree` в соседней директории `<project>-runs/session-NNNN`.
5. Запускает `scripts/run_session.py` внутри временного worktree.
6. Запускает проверки, по умолчанию `python -m pytest`.
7. Если всё успешно, коммитит изменения сессии и применяет их в основной проект через `git merge --ff-only`.
8. Если агент или проверки падают, удаляет временный worktree и ветку сессии.

Обычный `scripts/run_session.py` полезен для отладки и ручных запусков, но он пишет прямо в текущую директорию. Для автономного режима используйте `scripts/session_transaction.py`.

## Как направлять эксперимент

Редактируйте `GLOBAL_TARGET.md`. Пишите туда не конкретную команду "сделай X любой ценой", а направление:

- что сейчас важнее всего улучшать;
- какие виды артефактов полезны;
- чего избегать;
- как понять, что сессия была полезной.

Если нужно дать разовое сообщение, добавьте его в `state/external_messages.md`. Агент должен прочитать его, отреагировать и при необходимости перенести важное в план или знания.


## Вопросы создателю

Агент может задавать вопросы через файлы в `state/questions/`. Он создаёт отдельный markdown-файл с контекстом и разделом `## Ответ создателя`. Вы вписываете ответ в этот же файл и вручную запускаете следующую сессию.

Перед стартом транзакционной сессии runner автоматически делает checkpoint-коммит, если в основном проекте изменены только человеческие входы:

- `GLOBAL_TARGET.md`;
- `state/external_messages.md`;
- `state/questions/*.md`.

Если изменены другие файлы, запуск блокируется, чтобы не смешивать ручные правки с результатом автономной сессии.

## Ручной запуск

Запускайте сессии вручную, когда хотите дать агенту следующий ход:

`ash
python scripts/session_transaction.py --agent-command 'your-agent --cwd "{ROOT}" --prompt-file "{PROMPT_FILE}"'
` 

После сессии просмотрите изменения, при необходимости ответьте на вопросы в state/questions/ или обновите GLOBAL_TARGET.md, затем запустите следующую сессию вручную.

## Тесты

```bash
python -m pytest
```

## Ограничения

Этот каркас сам по себе не содержит модель и не устанавливает `mini-swe-agent`. Он подготавливает устойчивую файловую среду и единый промпт для любого агентного CLI. Это намеренно: модель, лимиты, стоимость и степень доступа к системе лучше выбирать явно.
