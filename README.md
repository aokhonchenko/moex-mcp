# Управляемый автономный AI-эксперимент

Это локальный каркас для эксперимента в стиле "AI lives on computer": агент вручную запускается создателем, читает файловую память, делает небольшой шаг, оставляет следы для следующей сессии и завершает работу.

Отличия этого варианта:

- все пользовательские артефакты пишутся на русском языке;
- человек направляет усилия через `GLOBAL_TARGET.md`;
- агент может задавать вопросы создателю через `state/questions/*.md`;
- автономные сессии запускаются атомарно через временный `git worktree`;
- модель подключается через `mini-swe-agent`, LiteLLM и OpenAI-compatible endpoint.

## Структура

```text
.
├── GLOBAL_TARGET.md              # Ваш текущий вектор: что улучшать и куда двигаться
├── SYSTEM_PROMPT.md              # Постоянные правила агента
├── AGENTS.md                     # Правила качества для агентов
├── config/
│   └── project.toml              # Настройки модели и mini-swe-agent
├── scripts/
│   ├── run_session.py            # Сборка промпта и запуск одной сессии в текущей папке
│   ├── run_mini_agent.py         # Non-interactive wrapper для mini-swe-agent
│   ├── sleep_memory.py           # Инструмент сна, вызываемый агентом внутри обычной сессии
│   └── session_transaction.py    # Атомарный запуск через временный git worktree
├── state/
│   ├── active_prompt.md          # Промпт, собранный для текущей сессии
│   ├── current_plan.md           # Рабочий план агента
│   ├── external_messages.md      # Сообщения от человека между сессиями
│   ├── questions/                # Вопросы агента и ответы создателя
│   ├── last_session.md           # Письмо следующей сессии
│   └── session_counter.txt       # Номер следующей сессии
├── logs/
│   └── history.md                # Хронология запусков и заметок
├── knowledge/                    # Устойчивые знания и наблюдения
├── projects/                     # Долгие проекты агента
├── tools/                        # Инструменты, которые агент создаёт для себя
└── tests/                        # Тесты runner'ов и транзакционной логики
```

## Сборка окружения

```bash
uv sync
```

`mini-swe-agent` установлен как dependency проекта и зафиксирован в `uv.lock`.

## Настройка OpenAI-compatible модели

Скопируйте пример окружения:

```bash
cp .env.example .env
```

Заполните `.env`:

```bash
AI_API_KEY=replace-with-your-api-key
AI_BASE_URL=https://your-openai-compatible-endpoint.example/v1
AI_MODEL=openai/your-model-name
```

Модель тоже хранится в `.env`, рядом с URL и ключом. `config/project.toml` содержит только не-секретные параметры запуска `mini-swe-agent`: лимиты шагов, cost tracking, timeout и путь к trajectory.

## Ручной запуск

Проверить сборку промпта без запуска модели:

```bash
uv run python scripts/run_session.py --dry-run
```

Запустить одну атомарную сессию вручную:

```bash
uv run python scripts/session_transaction.py
```

По умолчанию транзакционный runner вызывает:

```bash
uv run python scripts/run_mini_agent.py --root "{ROOT}" --prompt-file "{PROMPT_FILE}"
```

Если нужно заменить `mini-swe-agent` другим агентом, можно передать `--agent-command` явно.

## Атомарность

`session_transaction.py` обеспечивает правило: успешная сессия применяется целиком, упавшая сессия не меняет основной проект.

Порядок работы:

1. Проверяет, что основной проект является Git-репозиторием.
2. Загружает `.env` из основного проекта.
3. Если изменены только человеческие входы, делает checkpoint-коммит.
4. Проверяет, что основной worktree чистый.
5. Берёт `.session.lock`, чтобы две сессии не шли одновременно.
6. Создаёт временный `git worktree` в соседней директории `<project>-runs/session-NNNN`.
7. Запускает `scripts/run_session.py` внутри временного worktree.
8. Запускает `mini-swe-agent` через `scripts/run_mini_agent.py`.
9. Запускает проверки, по умолчанию `python -m pytest`.
10. Если всё успешно, коммитит изменения сессии и применяет их в основной проект через `git merge --ff-only`.
11. Если агент или проверки падают, удаляет временный worktree и ветку сессии.

Обычный `scripts/run_session.py` полезен для отладки и ручных запусков, но он пишет прямо в текущую директорию. Для автономного режима используйте `scripts/session_transaction.py`.


## Сон агента

Сон не запускается отдельной командой. Создатель запускает обычную сессию:

```bash
uv run python scripts/session_transaction.py
```

Агент сам решает, что пора спать, если накопилась усталость: много закрытых вопросов, шумная память, повторяющиеся действия или устаревшие решения. Внутри обычной сессии он может вызвать:

```bash
uv run python scripts/sleep_memory.py --root .
```

Сон архивирует закрытые вопросы из `state/questions/`, создаёт отчёт в `state/sleep/reports/`, обновляет `state/sleep/last_sleep.md` и оставляет будущей сессии более чистое состояние.

## Вопросы создателю

Агент может задавать вопросы через файлы в `state/questions/`. Он создаёт отдельный markdown-файл с контекстом и разделом `## Ответ создателя`. Вы вписываете ответ в этот же файл и вручную запускаете следующую сессию.

Перед стартом транзакционной сессии runner автоматически делает checkpoint-коммит, если в основном проекте изменены только человеческие входы:

- `GLOBAL_TARGET.md`;
- `state/external_messages.md`;
- `state/questions/*.md`.

Если изменены другие файлы, запуск блокируется, чтобы не смешивать ручные правки с результатом автономной сессии.

## Как направлять эксперимент

Редактируйте `GLOBAL_TARGET.md`. Пишите туда не конкретную команду "сделай X любой ценой", а направление:

- что сейчас важнее всего улучшать;
- какие виды артефактов полезны;
- чего избегать;
- как понять, что сессия была полезной.

Если нужно дать разовое сообщение, добавьте его в `state/external_messages.md`. Агент должен прочитать его, отреагировать и при необходимости перенести важное в план или знания.

## Ограничения

Этот каркас сам по себе не содержит API-ключ. Он подготавливает устойчивую файловую среду, единый промпт, атомарный запуск и интеграцию с `mini-swe-agent`. Модель, лимиты, стоимость и endpoint выбираются явно в `.env` и `config/project.toml`.
