## Структура папок

```
knowledge/
├── system_map.md          # Карта системы проекта
├── naming_rules.md        # Эти правила именования
├── projects/              # Папки для проектов (каждая — отдельная подпапка)
│   ├── {project-name}/    # Имя папки = имя проекта, в нижнем регистре
│   │   └── ...            # Файлы внутри проекта
├── notes/                 # Общие заметки без привязки к проекту
│   ├── 001-{тема}.md      # Числовое префиксирование для сортировки
│   └── {тема}-YYYY-MM-DD.md
├── tools/                 # Прототипы инструментов агента (скрипты, шаблоны)
│   ├── sleep/             # Инструмент сна и восстановления порядка
│   └── ...                # Другие утилиты
```

## Правила именования файлов

### 1. Общие правила

- **Язык:** русский для пользовательских артефактов; английский — для технических идентификаторов (имена переменных, команд).
- **Регистр:** нижний регистр (`snake_case` или `kebab-case`). Избегать заглавных букв.
- **Разделители:** дефис `-` между словами в именах файлов и папок.
- **Расширения:** `.md` для документации, `.py`/`.sh` для скриптов, `.json` для данных.

### 2. Имена проектов (в `knowledge/projects/{project-name}/`)

```
{project-name} = {категория}-{название}.md или .txt
               # Например: notes-идеи.md, tools-sleep.py
```

**Примеры:**
- ✅ `notes-идеи.md` — заметки по идеям проекта
- ❌ `Идеи_проект.txt` — не использовать кириллицу в именах файлов (использовать UTF-8 кодировку, но лучше латиницу)

### 3. Имена общих заметок (в `knowledge/notes/`)

```
{номер}-{тема}.md                    # Для хронологической сортировки
или {тема}-YYYY-MM-DD.md             # С датой для временных меток
```

**Примеры:**
- ✅ `001-первый-шаг.md` — первая заметка по теме "Шаги"
- ✅ `идеи-2026-07-06.md` — идеи от 6 июля 2026 года

### 4. Имена инструментов (в `knowledge/tools/`)

```
{категория}-{название}.{расширение}
# Например: tools-sleep.py, templates-question-template.md
```

**Примеры:**
- ✅ `tools-sleep-checklist.md` — чеклист для сна агента
- ❌ `sleep_tool_v1.py` — избегать версионирования в имени файла (использовать Git или метаданные)

### 5. Имена скриптов и утилит

```
{категория}-{название}.{расширение}
# Например: scripts-run-session.sh, tools-clean-logs.py
```

**Примеры:**
- ✅ `scripts-backup-knowledge.sh` — резервное копирование knowledge/
- ❌ `backup.sh` — слишком общее имя без контекста

## Правила именования папок внутри проектов

### 1. Структура проекта

```
knowledge/projects/{project-name}/
├── README.md              # Описание проекта и его целей
├── notes/                  # Заметки по проекту (использовать правила для заметок)
│   ├── 001-начало.md      # Первая заметка о проекте
│   └── ...                # Другие заметки
├── tools/                  # Инструменты, специфичные для проекта
│   └── {tool-name}.py     # Например: project-helper.py
├── data/                   # Данные и артефакты (если применимо)
│   ├── input.json         # Входные данные
│   └── output.txt         # Выходные результаты
└── logs/                   # Логи работы с проектом
    └── {date}.md          # Например: 2026-07-06.md
```

### 2. Имена файлов данных

```
{категория}-{название}.{расширение}
# Например: data-input.json, results-summary.txt
```

**Примеры:**
- ✅ `data-config-settings.json` — конфигурация проекта
- ❌ `config.json` — слишком общее имя без контекста

1. [ ] Файл относится к одной из категорий: проект, заметка, инструмент?
2. [ ] Имя использует нижний регистр и дефисы для разделителей слов?
3. [ ] Расширение соответствует типу содержимого (`.md`, `.py`, `.json`)?
4. [ ] Если это часть проекта — папка проекта существует или создана вместе с файлом?
