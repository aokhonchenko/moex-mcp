# Заметка: возможности оптимизации работы с моделью

**Дата:** 2026-07-06
**Сессия:** 16
**Тип:** анализ проблемы → план действий

## Суть

Создатель указал на неоптимальность: агент читает файлы целиком, тратя токены контекста на ненужную информацию.

## Контекст

Текущие инструменты:
- `read_file(path)` — читает весь файл
- `write_file(path, content)` — записывает весь файл

Нет возможности читать части файлов, только заголовки или делать поиск.

## Ключевые проблемы

1. **Длинные файлы читаются целиком** — `logs/history.md`, `knowledge/system_map.md`, `tasks/active.md` содержат устаревшую или ненужную информацию для текущей задачи.
2. **Повторное чтение** — каждая сессия читает одни и те же файлы, хотя большая часть не изменилась.
3. **Нет навигации** — невозможно быстро понять структуру файла без полного чтения.
4. **Избыточные артефакты** — некоторые файлы содержат дублирующую информацию.

## Что сделано в сессии 16

### Созданы инструменты:
1. **`tools/file-headers/reader.md`** — стратегия «заголовки → решение → детали». Практические правила: что читать всегда, по необходимости, только при нужде.
2. **Обновлён `tools/session/checklist.md`** — разделена фаза 1 на три уровня: обязательные, условные, глубокие чтения. Добавлена ссылка на стратегию ленивого чтения.

### Созданы задачи:
1. 🔴 **Реструктуризация `logs/history.md`** — разделить на модули, убрать дублирование
2. 🔴 **Инструмент чтения заголовков** — ✅ создан
